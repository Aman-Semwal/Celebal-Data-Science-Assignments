# API Documentation

Base URL (local): `http://localhost:8000`

Interactive OpenAPI docs are auto-generated by FastAPI at `/docs` (Swagger UI) and
`/redoc` (ReDoc).

## `GET /health`

Liveness/readiness check.

**Response** `200 OK`
```json
{
  "status": "ok",
  "model_loaded": true,
  "model_name": "catboost"
}
```
If no trained model is found on disk, `status` is `"degraded"` and `model_loaded` is
`false` — the endpoint itself never errors, so it's safe to use as a container health
check.

## `POST /predict`

Single-point prediction for one `(store, item, date)` combination.

**Request**
```json
{ "store": 1, "item": 1, "date": "2018-01-15" }
```

**Response** `200 OK`
```json
{
  "store": 1,
  "item": 1,
  "date": "2018-01-15",
  "predicted_sales": 14.32,
  "model_used": "catboost"
}
```

**Errors**
- `422` — invalid input (e.g. `store < 1`, malformed date)
- `404` — no history found for that (store, item) combination
- `503` — no trained model available

## `POST /forecast`

Full-horizon forecast (up to 90 days) for one `(store, item)` series, starting the day
after the last known date in the training history.

**Request**
```json
{ "store": 1, "item": 1, "horizon_days": 90 }
```

**Response** `200 OK`
```json
{
  "store": 1,
  "item": 1,
  "model_used": "catboost",
  "forecast": [
    { "date": "2018-01-01", "predicted_sales": 13.87 },
    { "date": "2018-01-02", "predicted_sales": 12.45 }
  ]
}
```

## `GET /model-info`

Metadata about the currently served model.

**Response** `200 OK`
```json
{
  "model_name": "catboost",
  "feature_count": 48,
  "validation_metrics": {
    "rmse": 7.56, "mae": 5.82, "mape": 12.78, "smape": 12.27, "wape": 10.65,
    "fit_seconds": 263.3
  },
  "available_models": ["catboost", "xgboost", "lightgbm_tuned", "lightgbm", "random_forest"]
}
```

## Model Selection

The API always serves the best available model, chosen by trying each name in
`_MODEL_PREFERENCE` (`src/deployment/inference.py`) in order and using the first one
found on disk: `catboost > xgboost > lightgbm_tuned > lightgbm > random_forest`. The
Attention-LSTM is intentionally excluded from API serving (see `docs/model_documentation.md`
for why) but remains available for analysis via its own module.

## Example: `curl`

```bash
curl -X POST http://localhost:8000/predict \
  -H "Content-Type: application/json" \
  -d '{"store": 1, "item": 1, "date": "2018-01-15"}'
```
